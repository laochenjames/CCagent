# 实施方案 v2.2：详细分析报告——排版优化 + 下载

本文档是对 v2/v2.1 的补充，交给 AGENT 执行。范围：(1) 重做"详细分析"的排版；(2) 提供报告下载。**不改动评分模型、规则引擎、LLM 调用与 prompt、清单与保存逻辑。**

## 0. 现状与问题（基于 `app.js` 的 `renderAnalysis` 与 `index.html`）

1. 详细分析由前端用字符串拼 `innerHTML` 渲染，层次扁平：因子、智囊、批判、验证设计各一个标题加一堆文字。
2. **批判条目显示的是原始 id**（如 `[paid_evidence]`、`[MONETIZATION]`），用户看不懂；智囊的"缺失字段"同样是 id。
3. 评级只是括号里的文字，没有视觉区分；`rule_note` 与 LLM 文字混在一起，看不出哪些是程序算的、哪些是 AI 写的。
4. 验证设计里的"【用户确认】/【AI建议值】"标记直接露在正文里。
5. **安全问题：** `renderAnalysis` 把 LLM 生成的文字（可能含用户原话）直接拼进 `innerHTML`，没有转义。本地单用户暂时问题不大，但将来公网部署前必须消除。
6. 没有下载能力。

## 1. 总体方案

**单一渲染源：** 新增 `report.py`（纯函数，仅依赖标准库）和 `report.css`。服务端用同一套代码生成：
- 页面内"详细分析"的 HTML 片段（fragment）；
- 可下载的完整报告（自包含 HTML、Markdown）。

这样页面和下载文件版式一致，转义也只在一处做。前端不再自己拼详细分析的 HTML，改为请求服务端片段后插入。

**下载格式（默认）：** 自包含 HTML（含内联 CSS，可离线打开，自带打印样式，浏览器里"打印 → 另存为 PDF"即得 PDF）+ Markdown。**不做 PDF/Word 直出**：不引入第三方依赖，纯标准库生成含中文的 PDF 不现实。

## 2. 报告内容与版式

### 2.1 完整报告的章节顺序（下载文件）
0. **报告头**：标题"职业投入体检报告"；决策一句话（`result.decision`，为空则用会话标题）；生成时间（服务端本地时间，格式 `YYYY-MM-DD HH:MM`）；分析生成时间与所用模型（见 4.3）；右上角"打印 / 另存为 PDF"按钮（`no-print`）。
1. **评估摘要**：评估词（大字）、行动词、置信度进度条、"可能范围 low–high" 与静态刻度条（纯 CSS，用内联 `style` 设置区间与标记点位置，不依赖 JS）、`headline`。
2. **风险提示**：红/黄两种样式；红色与黄色同时有文字标签"红"/"黄"（不只靠颜色）。无风险时显示"未发现明确风险（不代表没有风险）"。
3. **你提供的信息**：按分组（基本情况、变现与需求、时间与执行、划算程度、财务安全垫、止损设置）的表格：项目 | 你的回答 | 可信度。可信度的显示文案：事实→"有记录可查"，自报→"自己报的"，估计→"有依据的估计"，猜测→"不太确定"。未提供的项目归入同一表格末尾的"未提供"行（列出 `ui_label`，不显示 id）。仅列 `ui_show=true` 的字段。
4. **评分依据**：因子表格：因子 | 评级徽章 | 依据（`rule_note`）| 可能范围（`interval`）。评级为"无法判断"的行标注"信息不足，按未知处理"。
5. **智囊会诊**：卡片网格（桌面两列，窄屏一列）。每张卡片：名称与一句话维度（取自智囊库 `dimension`）、评级徽章（AI_IMPACT 与 CONSISTENCY 显示"不评级"）、依据（`basis`）、提示（`note`，非空才显示）、**缺少的信息**（把 `missing` 里的字段 id 转成 `ui_label`）。需要评级的 5 位在前，AI_IMPACT 与 CONSISTENCY 放在"其他提示"小标题下。
6. **假设批判**：列表。每条前面是"针对"标签：`target` 若是字段 id 则显示该字段的 `ui_label`，若是智囊/因子 id 则显示其中文名，无法映射则不显示标签。
7. **两周内可验证的 3 件事**：编号列表；每条前有"需求侧/供给侧"小标签；需求侧用实心边框，供给侧用虚线边框（不只靠颜色）。
8. **验证设计**：三块纵向排列（宽屏可三列）："供给侧（你能控制的行为）"、"需求侧（陌生人的真实反应）"、"止损与继续条件"。止损块里每条末尾的"【用户确认】/【AI建议值】"从正文剥离，渲染为徽章"用户确认"/"AI 建议值"。
9. **如何让评估更准**：取 `groups` 中 `gain` 最高的前 3 组，列出其中仍未填写的项目（`ui_label`）和"补全可提升置信度约 +N%"；全部已补全时本节省略。
10. **说明**：固定文案——"评分、评级和风险提示由程序按固定规则计算；依据、批判和验证建议由 AI 根据你提供的信息生成，仅供参考。"+ `DISCLAIMER`；若 `analysis.hidden_count > 0`，追加"另有 N 条 AI 文字因含未核实数字被隐藏"；若分析已过期（`stale`），在**报告头下方**加醒目提示"详细分析基于较早的信息，你之后修改过部分项目"。

另附：折叠块"你的原始描述"（`<details>`，默认收起，打印时隐藏），内容为 `raw_text`（转义后原样显示）。

### 2.2 页面内的详细分析（片段）
只包含第 4–8 节。顶部仪表盘、清单已承担摘要、风险和信息展示，不重复。片段根节点为 `<div class="rp rp-fragment">`。

### 2.3 样式规范（`report.css`）
- 根容器 `.rp`：最大宽度 760px、居中；字体沿用系统字体栈；行高 1.6；段间距统一。
- 各章 `.rp-section`：标题 `h2` 前自动编号（CSS counter，在 `.rp` 上 `counter-reset`），章与章之间用细线分隔，章内留白一致。
- 徽章 `.rp-badge`（评级、用户确认、AI 建议值等）：圆角小标签，**文字必须出现**，并用不同边框样式区分：高=实线加粗，中=实线，低=虚线，无法判断/不评级=点线。颜色只做辅助。
- 表格 `.rp-table`：窄屏下可横向滚动（外层 `overflow-x:auto`），行线细，表头弱化。
- 卡片 `.rp-card`：边框、圆角、内边距一致；`break-inside: avoid`。
- 摘要刻度条：高度 12px，区间用半透明，标记点用实心竖条，标注"偏低/一般/偏高"三区间文字。
- 移动端（≤ 640px）：卡片单列，字号不小于 14px。
- **打印样式** `@media print`：`@page { size: A4; margin: 16mm; }`；隐藏 `.no-print`；背景白色；`.rp-card`、表格行、徽章 `break-inside: avoid`；章标题 `break-after: avoid`；设置 `-webkit-print-color-adjust: exact; print-color-adjust: exact;` 保证刻度条与徽章边框能印出；`<details>` 原始描述在打印中隐藏。
- 不使用任何外部字体、图片、脚本。下载 HTML 仅包含一个内联 `<script>`：给"打印"按钮用的 `window.print()`（或直接用 `onclick`）。

## 3. 后端改动

### 3.1 新增 `report.py`
纯函数，无 I/O。建议接口：
- `build_fragment(result, analysis, registry, advisors) -> str`：第 4–8 节的 HTML 片段。
- `build_full_html(result, analysis, registry, advisors, meta, css_text) -> str`：完整自包含 HTML（`meta` 含标题、raw_text、stale、generated_at、model、groups 等）。
- `build_markdown(result, analysis, registry, advisors, meta) -> str`：同章节顺序的 Markdown。表格使用 Markdown 表格；徽章用"【高】/【中】/【低】/【无法判断】"文字；需求侧/供给侧用"需求侧｜"/"供给侧｜"前缀。
- `safe_filename(title, dt) -> str`、`format_value(field_def, value) -> str`、`label_for_target(target, registry, advisors) -> str|None`。

规则：
- **所有动态文本必须经 `html.escape(..., quote=True)` 后再输出到 HTML**。Markdown 中对 `\ ` * _ # | < > [ ]` 做转义；表格单元格内的换行替换为空格。
- 值格式化：bool→"是/否"；enum→对应 `choices` 的 label；number→带 `unit`（`take_home_ratio` 按百分比显示，如 70%）；list（`past_projects`）→每项一行"计划 x 月，实际 y 月，仍在做/已结束"；None/缺失→"未提供"。
- 验证设计里的标记：用正则识别末尾的 `【用户确认】`、`【AI建议值】`，剥离后渲染为徽章；其他位置出现的同样字样不做处理。
- 报告不得包含任何外部 URL（`http://`、`https://`）、`<link>`、`<img>`、`<script src>`。

### 3.2 新增静态文件
`report.css` 加入 `ALLOWED_STATIC_FILES`。下载 HTML 时读取该文件内容内联到 `<style>`。

### 3.3 新增 API
`GET /api/sessions/{id}/report?format=fragment|html|md`

| format | 响应 |
|---|---|
| `fragment` | `200 application/json`：`{"html": "...", "stale": bool, "generated_at": "...", "model": "..."}` |
| `html` | `200 text/html; charset=utf-8`，附件下载 |
| `md` | `200 text/markdown; charset=utf-8`，附件下载 |

- 下载响应头：`Content-Disposition: attachment; filename="report.html"; filename*=UTF-8''<百分号编码的中文文件名>`（Markdown 同理，扩展名 `.md`）。文件名格式：`职业投入体检报告_{标题前20字}_{YYYYMMDD-HHMM}.{ext}`；标题中的 `\ / : * ? " < > |` 与控制字符替换为 `_`；标题为空用"未命名"。
- 尚未生成详细分析：`409 {"error":"尚未生成详细分析","category":"未生成"}`。
- 会话不存在：404。沿用现有 Host/Origin 校验。
- 下载使用服务端存的**最新结果与缓存的详细分析**。分析已过期时仍可下载，按 2.1 第 10 节标注。

### 3.4 `server.py` 其他改动
- `_handle_analysis` 保存分析时，在 `analysis_obj` 中增加 `generated_at`（UTC ISO）与 `model`（实际使用的模型名）。旧数据没有这两项时，报告中对应位置显示"—"，不报错。
- 其余逻辑不变。

## 4. 前端改动（`app.js`、`index.html`、`style.css`）

1. `index.html` 引入 `report.css`；详细分析区改为：`#analysis-body` 只放一个容器 `#analysis-html`，原来的 `#factors-table`、`#advisors-list`、`#critique-list`、`#checks-list`、`#validation-design` 及对应标题全部删除。
2. 删除 `renderAnalysis` 里所有 `innerHTML` 拼接。新逻辑：分析生成成功或打开已有分析的会话后，请求 `format=fragment`，把返回的 `html` 赋给 `#analysis-html.innerHTML`（片段已在服务端转义，前端不得再拼接任何来自 LLM 或用户的字符串）。
3. 详细分析标题行增加下载按钮：`下载报告（HTML）`、`下载 Markdown`。点击后用 `window.location.href = /api/sessions/{id}/report?format=html`（或 `md`）触发下载。分析尚未生成时按钮禁用，并显示"生成详细分析后可下载"。
4. 过期提示（`stale`）沿用现有横幅；过期时下载按钮仍可用，旁边提示"下载内容会标注分析已过期"。
5. 仪表盘吸顶、清单、保存队列等其余前端逻辑不变。

## 5. 测试与验收

### 5.1 自动测试（`tests/test_report.py`，不依赖网络）
1. **转义**：分析文字中含 `<script>alert(1)</script>`、`"` 与 `&`，输出的 HTML 中不得出现原样的 `<script>alert`，应为转义后的实体；Markdown 中特殊字符被转义。
2. **标签映射**：批判 `target="paid_evidence"` 渲染为对应 `ui_label`；`target="MONETIZATION"` 渲染为"变现与需求官"（智囊名）；未知 target 不渲染标签；输出中不得出现原始字段 id。
3. **缺失字段**：智囊卡片的"缺少的信息"显示 `ui_label`，不显示 id。
4. **徽章与标记**：验证设计里末尾的"【AI建议值】"被剥离并渲染为徽章；正文中不残留该标记。
5. **值格式化**：bool、enum、number（含单位）、`take_home_ratio` 百分比、`past_projects` 列表、缺失值。
6. **章节顺序**：完整 HTML 与 Markdown 的章节标题按 2.1 的顺序出现；无可补全项时第 9 节省略。
7. **自包含**：完整 HTML 不含 `http://`、`https://`、`<link`、`<img`、`<script src`。
8. **过期与隐藏提示**：`stale=true` 时报告头下方出现过期提示；`hidden_count > 0` 时出现隐藏说明。
9. **文件名**：含非法字符与中文的标题被正确清理并截断；`Content-Disposition` 同时含 ASCII 回退名与 `filename*`。
10. **接口**：无分析时三种 format 均返回 409；会话不存在返回 404；`fragment` 返回的 JSON 含 `html`。
11. 旧数据（`analysis` 无 `generated_at`/`model`）能正常生成报告。

### 5.2 手动验收（逐条勾选，结果记入 `tests/golden/RESULTS.md`）
1. 生成详细分析：页面内的详细分析显示为新版式——章节有编号和分隔、评级徽章带文字、批判和缺失信息全是中文标签，无任何原始 id。
2. 点"下载报告（HTML）"：得到文件，**断网状态下双击打开**，版式与页面一致，含摘要、风险、已填信息表、评分依据、智囊卡片、批判、两周验证、验证设计、"如何让评估更准"、说明。
3. 在浏览器里"打印 → 另存为 PDF"：A4 排版正常，卡片和表格行不被分页切断，刻度条与徽章边框能印出，"打印"按钮不出现在 PDF 里。
4. 点"下载 Markdown"：内容完整、表格正常、无原始 id。
5. 在详细分析生成后修改一个清单项，再下载：报告头下方出现"分析已过期"提示，摘要里的分数使用最新结果。
6. 手机宽度（≤ 640px）：页面内详细分析与下载 HTML 均为单列，表格可横向滚动。
7. 中文文件名在 Windows 上正常保存，不乱码。
8. 在用户描述或字段中人为放入 `<b>x</b>` 之类文本，生成分析和下载后，页面与文件里都按文字显示，不被当作标签渲染。
