# 实施方案 v2.3.1：上线最小补丁

目标：**只做上线必需项**，不追求完善。范围假设为"本机或小范围自用上线"。公网部署所需（限流、日限额、登录、输入是否落库、付费 Key）不在本方案内，见第 4 节。

原则：
- 每项先写测试再改代码；不得为让评分"更好看"而改任何阈值。
- 前端不计算评分、评级、风险。
- 完成后交回：改动文件清单、`python -m unittest discover tests -v` 输出、`python tools/calibrate.py` 输出、第 3 节逐条自查表。

## 1. 必做（阻断上线）

### 1.1 修复 `log_event` 导致的 500（P0）
**现象**：`server.py` 中 `log_event(level, event, session, version, length, ms, category)` 不接受 `tokens`、`stale`，但 `_handle_analysis`（`analysis_ok`）与 `_handle_append_text`（`append_text_ok`）的成功日志传了这两个参数，抛 `TypeError`，被 `do_POST` 兜底成 HTTP 500。此时数据已入库，但页面报错、不渲染。

**做法**：
- `log_event` 增加 `**extra`，把额外的键值（只允许数字或布尔）追加到日志行，例如 `tokens=1234 stale=False`；字符串类型的额外参数一律丢弃（防止用户文本进日志）。
- 新增集成测试（**mock `llm.call_gemini`，不联网**）：
  - `/analysis` 成功路径返回 200，且响应含 `analysis` 与 `stale`；
  - `/append-text` 成功路径返回 200，版本号加 1；
  - 两条路径下日志中不含用户原文。

### 1.2 枚举校验失效
`_handle_fields_update` 读取 `fdef.get("options")`，注册表使用的是 `choices`（元素为 `{value,label}`），校验从不触发。
- 改为读取 `choices` 的 `value` 集合；值不在集合内返回 400（`category: 参数错误`）。
- 兼容现有对 `options` 的读取：`choices` 优先，没有再读 `options`。
- 测试：对 `paid_evidence` 提交非法值返回 400；合法值返回 200。

### 1.3 清空输入框不生效
**现象**：前端 `readNum()` 在输入框被清空时返回 null，不发请求；服务端因此保留旧值，评分不变，也没有提示。

**做法**：
- 前端：数字与文本输入框在内容被清空并失焦（或回车）时，发送 `{"id":..., "clear":true}` 作为 `fields` 项（走现有 `/fields` 接口，不新增路由）。
- 服务端：`clear:true` 的字段状态改为 `status:"missing"`、`value:null`（保留 id 与 unit）；对 `value` 为 `None` 或空串且没有 `clear` 的提交，**不写入**（既不置 given，也不报错，直接忽略）。
- 测试：填入后清空，`status` 变为 `missing`，评分按未填重算；空串提交不会使字段变为 given。

### 1.4 安全垫：未填"仍有收入"时的处理（决策：方案 C）
**现状**：实现一律评"中"，并带有一行多余的覆盖代码；与 v2.3 方案 2.3 的 min(中, 毛评级) 不一致。

**决策（可被用户推翻）**：未填 `income_after_monthly` 时，**信号 S 不评**（视为未知），只保留信号 O（花费占比）和黄色标志。
- `rate_safety_net`：`income_after is None` 时不向 `signals` 追加任何 S 信号，仅在 `notes` 里写"未确认现有收入是否继续，生存月数未计入评级"。
- 若 O 也无法计算 → 返回"无法判断"。
- 黄色标志（`compute_flags`）保持不变：毛月数 <3 时提示"如果这段时间没有稳定收入，现金大约只够 X 个月"。
- 红线逻辑不变（仍只在 `income_after` 已提供且净消耗下 <3 个月时触发）。
- 删除多余代码行。
- 测试更新：
  - 未填收入、毛月数 <3、无 `cash_outlay` → 评级"无法判断"，无红线，有黄色标志；
  - 未填收入、有 `cash_outlay` 占比 <10% → 评级"高"（仅由信号 O 决定）；
  - 已填收入的分支行为不变。
- 在 `tests/golden/RESULTS.md` 的手动验收第 1 条同步改为：风险条出现黄色提示、没有红线、评估词不是"不建议投入"（不再要求安全垫评中）。

### 1.5 红线时不显示置信度
**现状**：红线触发时区间被封顶为 15–25，但置信度仍按封顶前计算（用例 2、5、6 分别显示 20%、19%、17%），与"不建议投入"并列容易误读。

**做法（只改展示）**：
- `compute_score` 的 `score` 对象新增 `red_line: true|false`；**不改** `_raw_confidence`（清单增益计算依赖它）。
- 前端：`red_line` 为 true 时，隐藏置信度条与百分比，改显示一行"由规则直接判定（红线）"；吸顶紧凑模式同样处理。
- 历史列表：红线会话不显示"置信度 X%"，显示"红线"。
- 测试：用例 2、5、6 的 `score.red_line` 为 true；用例 1 为 false。

### 1.6 排除开关的提示补全
- `score.excluded` 每项增加 `rating_if_included`：对**用户手动排除**的因子，用 `engine.rate_*` 在不考虑排除的情况下算一次评级；学习型自动排除不计算（置 `null`）。
- 仪表盘"评分未包含"一行、报告摘要与"评分依据"表下的注释，在 `rating_if_included` 为"低"时显示"（若计入将评为低）"。
- 测试：手动排除一个本应评"低"的因子，`excluded[0].rating_if_included == "低"`；学习型自动排除为 `null`。

### 1.7 删除误路由
`do_DELETE` 中对 `/report` 路径调用 `_handle_report` 的分支删除；该路径返回 404。
