# 实施方案 v2.4：对外开放（免费额度 + 自带 Key：Gemini / Grok / DeepSeek）

## 范围与假设

- 单进程 Python 服务，放在 HTTPS 反向代理之后；SQLite；服务器持有一个 **Gemini 付费档** Key，供免费额度使用。
- 自带 Key 只支持三家：Gemini、Grok（xAI）、DeepSeek。**不提供自定义 Base URL**，三家的地址写死在预设里。
- 不做：登录、支付、其他厂商（OpenAI、Anthropic 等）、自定义 Base URL、多进程部署。
- 分三期，可以分别上线。第一期不含自带 Key；第二期只加 Gemini 自带 Key；第三期加 Grok 和 DeepSeek。
- 默认决策（可推翻）：每次调用模型算 1 次免费额度，每个匿名用户每天 10 次；不做登录，用 Cookie 加 IP 识别；自带 Key 只存浏览器；会话存服务端，保留 30 天。

通用原则：先写测试再改代码；不改评分规则，不改 `RULES_VERSION`；日志中不得出现用户文字或任何 Key；每期完成后交回改动文件清单、`python -m unittest discover tests -v` 完整输出、`python tools/calibrate.py` 输出（四项硬性验收不得变化）。

## 0. 模式与配置

新增环境变量（`.env` 或系统环境均可，托管模式下以系统环境为准）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOSTED` | 0 | 1 为托管（对外）模式 |
| `ALLOWED_HOSTS` | 空 | 托管模式下允许的 Host，逗号分隔，只比较主机名 |
| `TRUST_PROXY` | 0 | 1 时取 `X-Forwarded-For` 的最后一个值作为客户端 IP |
| `FREE_DAILY_LIMIT` | 10 | 每个匿名用户每天的免费调用次数 |
| `FREE_DAILY_LIMIT_IP` | 30 | 每个 IP 每天的免费调用次数 |
| `GLOBAL_DAILY_LIMIT` | 300 | 全站每天的免费调用总数（熔断） |
| `RETENTION_DAYS` | 30 | 会话保留天数 |
| `QUOTA_SALT` | 无 | IP 哈希用的随机盐；托管模式下缺失则拒绝启动 |
| `GEMINI_API_KEY` | 无 | 托管 Key；托管模式下只从系统环境读取，不写 `.env` |

非托管模式（本机自用）行为保持不变：不要求 Cookie，不校验归属，不计额度。

新增接口 `GET /api/mode`，返回 `{hosted, free_limit, retention_days}`，前端据此调整界面。

## 第一期：对外开放的最低门槛

### 1.1 托管模式的安全收口
- Host 校验：`HOSTED=1` 时只允许 `ALLOWED_HOSTS` 中的主机名；Origin 的主机名也必须在其中。非托管模式沿用 localhost。
- 托管模式下这三个接口一律返回 404：`/api/save-config`、`/api/config`、`/api/test-connection`（第二期以新形式恢复 test-connection）。
- 托管模式下 `validate_base_url` 不再被任何请求路径使用；`call_gemini` 的 Base URL 固定为官方地址，不接受请求传入。
- POST 必须是 `Content-Type: application/json`，否则返回 415。
- 请求体上限 64 KB，超出返回 413；`_read_json_body` 在读取前检查 `Content-Length`。
- 处理器设置 `timeout = 30`，防止慢连接占线程。
- 响应头（所有响应）：`X-Content-Type-Options: nosniff`、`Referrer-Policy: no-referrer`、`X-Frame-Options: DENY`。
- 可选：对页面加 CSP（`default-src 'self'`），启用前手动确认页面和报告片段显示正常。

### 1.2 匿名身份（Owner）
- Cookie `cc_owner`：32 字节 URL 安全随机串，`HttpOnly`、`SameSite=Lax`、`Path=/`、托管模式加 `Secure`，有效期一年。
- 服务端只保存其 SHA-256 作为 `owner_hash`，不保存原始值。
- 没有 Cookie 的请求，服务端生成新的并在响应里 `Set-Cookie`。
- 客户端 IP：`TRUST_PROXY=1` 时取 `X-Forwarded-For` 最后一个值，否则取连接地址。反向代理必须用连接地址**覆盖**该头，不能追加客户端传来的值（nginx：`proxy_set_header X-Forwarded-For $remote_addr;`，Caddy 默认即覆盖）。
- IP 存储前做 `sha256(QUOTA_SALT + ip)`，不保存原始 IP。

### 1.3 会话隔离
- `sessions` 表增加 `owner_hash TEXT` 列（`ALTER TABLE`，并建索引）。旧会话该列为 NULL，托管模式下不可见。
- `store.create_session` 增加参数 `owner_hash`。
- `store.list_sessions` 在托管模式下只返回 `owner_hash` 等于当前用户的会话。
- 所有按会话 ID 访问的接口（读取、`fields`、`append-text`、`analysis`、`report` 各格式、`DELETE`）统一经过一个归属校验函数：托管模式下归属不符一律返回 **404**（不用 403，避免泄露存在性）。
- 会话 ID 改为 `s_<时间戳>_<token_urlsafe(12)>`。旧格式 ID 继续可用（非托管模式）。更新依赖 ID 格式的测试。
- `_session_locks` 不再无限增长：改为固定数量（如 64 个）的分片锁，按会话 ID 哈希取模。

### 1.4 免费额度
- 新增 `quota.py` 与表 `usage(day TEXT, subject TEXT, n INTEGER, PRIMARY KEY(day, subject))`。subject 三类：`o:<owner_hash>`、`i:<ip_hash>`、`g:all`。
- `day` 取新加坡时间（UTC+8）的日期，使用固定偏移，不依赖时区库。
- `reserve(owner_hash, ip_hash)`：在一个 `BEGIN IMMEDIATE` 事务里检查三个上限，全部通过才同时加 1，否则不改任何计数并返回哪一项用完。
- `refund(...)`：模型调用失败（包括解析失败）时退回这次占用。
- 只有使用托管 Key 的调用才占用额度：`/api/evaluate`、`/append-text`、`/analysis`。改字段不调模型，不计数。
- 额度用完返回 HTTP 429，`category` 为"额度用完"，`error` 写明哪一项用完（个人 / IP / 全站）和恢复时间（次日 0 点新加坡时间）。
- 每个会调用模型的响应，以及新增的 `GET /api/quota`，都带 `quota: {limit, used, remaining, resets_at}`。

### 1.5 访问频率限制（非模型）
- 新增 `ratelimit.py`，内存令牌桶，按 IP：所有 `/api/` 请求 120 次/分钟，超出返回 429。
- 单进程内有效即可。

### 1.6 数据保留
- 启动时和之后每 6 小时，后台线程删除 `updated_at` 早于 `RETENTION_DAYS` 的会话（含其评估记录）。同时清理 30 天前的 `usage` 行。
- 页面上写明保留期，已有的"删除"按钮保留。

### 1.7 前端
- 顶栏显示"今日免费额度 x/10"（托管模式），额度为 0 时弹出提示，指向第二期的"使用自己的 Key"。
- 页面底部增加折叠的"隐私与数据"说明：保存哪些内容（你的描述、填写的数字、评估结果）；保留 30 天；描述会发送给模型服务（默认 Google Gemini）；记录与本浏览器绑定，清除 Cookie 后看不到旧记录；可随时删除。
- 托管模式下隐藏现有"设置"弹窗中的服务端 Key 与 Base URL 部分。

### 1.8 测试（全部不联网）
- 归属隔离：用户 B 对用户 A 的会话，在读取、`fields`、`append-text`、`analysis`、`report`（三种格式）、`DELETE` 上全部得到 404；B 的列表中没有 A 的会话。
- 托管模式下 `save-config`、`config`、`test-connection` 返回 404；非托管模式保持原行为。
- Host 白名单：非白名单 Host 返回 403；白名单 Host 正常。
- 415（非 JSON）、413（超过 64 KB）。
- Cookie 属性：托管模式含 `HttpOnly`、`Secure`、`SameSite=Lax`；数据库中不含原始 Cookie 值。
- 额度：20 个线程并发 `reserve`，上限 10 时恰好 10 个成功；失败退款后可再次成功；个人、IP、全站三种上限各有一个用例；新加坡时间跨天后重置（注入时钟）。
- 额度用完返回 429 且响应含 `quota`；改字段在额度用完后仍可用。
- 保留期清理：构造过期会话，清理后消失，未过期的保留。
- 频率限制：超过阈值返回 429。

## 第二期：自带 Key（先只支持 Gemini，传输层一次做好）

### 2.1 传输
- 前端对三个会调用模型的接口，以及自测接口，附带请求头：`X-LLM-Provider`、`X-LLM-Key`、`X-LLM-Model`。Key 只放请求头，不放 URL、不放请求体。
- 服务端检测到 `X-LLM-Key`：使用该 Key，**不占用免费额度**；`provider` 必须在 `gemini`、`xai`、`deepseek` 中（本期只接受 `gemini`，其余返回 400"暂不支持"）；`model` 经 `sanitize_model`；忽略请求里的任何 Base URL。
- 自带 Key 无效时直接报错，**不得悄悄改用托管 Key**。
- 服务端不保存、不记录该 Key。任何异常信息、日志、`GeminiAPIError.message` 都不得包含 Key。

### 2.2 自测接口 `POST /api/test-connection`（托管模式下恢复）
- 只接受上述请求头，不接受 Base URL。
- 每 IP 每小时最多 10 次；不占免费额度。
- 先发一次最小调用验证 Key 和模型名；再跑一次固定文本的抽取：输入"想业余做技能陪跑，单价800元，自己能拿7成"，检查：返回合法 JSON、顶层含 `decision`、`extracted`、`clarify`，且抽到 `unit_price` 为 800。
- 返回 `{ok, parsed_ok, extracted_ok, message}`：能解析但没抽到单价时提示"该模型可用，但抽取质量不足，建议换模型"。

### 2.3 前端设置弹窗（两种模式通用）
- 厂商下拉、Key 输入框（密码框）、模型名输入框（带该厂商默认值）、"测试连接并自测"按钮。
- "保存在本浏览器"复选框，默认不勾选：不勾选时 Key 只留在页面内存，刷新即失效；勾选才写入 `localStorage`。旁边提示"公共电脑不要勾选"。
- 保存后不回显 Key，只显示掩码。
- 使用自带 Key 时，顶栏显示"使用你自己的 Key，不占免费额度"。
- 选择厂商时显示一句提示：你的描述会发送给该厂商，按其数据政策处理。
- 非托管模式保留原"服务器默认（仅本机）"区块，原行为不变。

### 2.4 测试
- 带 `X-LLM-Key` 的请求不占用额度；无效 Key 返回错误，不回退到托管 Key（mock 断言托管 Key 从未被使用）。
- 日志、异常响应中不含 Key（构造含 Key 的请求，断言 stdout 与响应体中都没有）。
- 非法 `provider` 返回 400；请求带 Base URL 被忽略。
- 自测接口：合法响应通过；无法解析、未抽到单价各一个用例；频率限制生效。

## 第三期：Grok 与 DeepSeek

### 3.1 结构
- 新增 `providers.py`，提供统一入口 `call_model(provider, api_key, model, task, user_message, ...)`，返回解析后的字典（带 `_usage`）。`gemini` 沿用现有实现，新增一个 OpenAI Chat Completions 适配器，用两个预设驱动：

| 预设 | Base URL（写死） | 结构化输出 |
|---|---|---|
| `xai` | `https://api.x.ai/v1` | `response_format: json_schema` |
| `deepseek` | `https://api.deepseek.com` | `response_format: json_object` |

- `server.py` 改调 `llm.call_model`（内部分派），测试里相应改 patch 目标；`GeminiAPIError` 保留并加别名 `LLMError`。
- 默认模型写在配置常量里，便于以后修改：DeepSeek 默认 `deepseek-v4-flash`；xAI 的默认值由实施者查 `docs.x.ai` 当前文档后设定，优先选非推理的快速型号，不要硬编码在多处。模型名由用户可改，经 `sanitize_model`。

### 3.2 OpenAI 适配器规格
- 请求：`POST {base}/chat/completions`，请求头 `Authorization: Bearer <key>`；`messages` 为一条 system 加一条 user；`temperature` 0.2；按任务设置 `max_tokens`（抽取 2048，分析 6000，常量可调）。
- 结构化输出：
  - `xai`：把现有 Gemini 风格的 Schema（大写类型名）转换成标准 JSON Schema：类型名小写；每个 object 加 `additionalProperties:false`；所有属性都列入 `required`。转换函数单独实现并单测。
  - `deepseek`：只用 `json_object`。在 system 提示末尾追加一段，**必须包含 "json" 字样**，并给出由 Schema 自动生成的 JSON 示例。
- 解析：取 `choices[0].message.content`，去掉代码围栏后解析。
  - `finish_reason == "length"`：报错"输出被截断，请缩短输入或换模型"。
  - 内容为空或只有空格（DeepSeek 在输出无法识别为 JSON 时会这样）：重试一次，仍为空则报错。
  - JSON 解析失败：同样重试一次。
- 用量：映射 `usage.prompt_tokens`、`completion_tokens`、`total_tokens` 到 `_usage`。
- 思考/推理：
  - DeepSeek V4 默认开启思考，抽取和分析都应关闭，请求里带该厂商文档规定的关闭参数（实施前对照 DeepSeek 思考模式文档确认参数名与取值）。
  - 其他厂商专有参数一律走"被拒绝则去掉重试"的模式，**只有重试成功后才记住该参数不被支持**（本次审阅在 `call_gemini` 里发现的同类问题，同步修掉）。
  - xAI 不主动发送推理参数，避免 400。
- 错误映射：401/403 → Key 无效；402 → 余额不足（DeepSeek）；404 → 模型名不存在；422 与 400 → 请求被拒绝；429、5xx → 沿用现有的重试一次规则；超时、网络错误沿用现有处理。
- 自测的第一步改为：先 `GET {base}/models` 验证 Key 并确认模型名在列表中（不消耗 token），再跑固定文本抽取。Gemini 沿用最小调用。
- 日志增加 `provider` 与 token 数，仍不含任何用户文字和 Key。

### 3.3 前端
- 厂商下拉增加 Grok（xAI）与 DeepSeek，各带默认模型名。
- 分析报告的"模型"一栏显示"厂商 / 模型名"。

### 3.4 测试（mock `urlopen`）
- `xai`：请求体含 `response_format.type == "json_schema"`、类型名全为小写、每个 object 含 `additionalProperties:false`。
- `deepseek`：请求体含 `json_object`，system 提示含 "json" 字样和示例。
- 空内容、仅空格、`finish_reason: length`、非法 JSON 各一个用例。
- 401、402、404、429、5xx 的错误映射。
- 参数被拒绝重试：首个 400 带推理参数、重试成功后才置位；[400, 400] 时不置位，且下一次请求仍带该参数。
- Schema 转换函数：嵌套 object、array、enum 的转换结果。
- Gemini 路径行为不变，原有 `test_llm.py` 保持通过。

## 验收

### 自动
- 全部测试通过；校准四项硬性验收不变：用例 1 无红线；用例 2、5、6 有红线；用例 8 评估词"还看不出来"。

### 手动（托管模式，用两个浏览器或一个无痕窗口）
1. 浏览器 A 创建会话；浏览器 B（不同 Cookie）打开 A 的会话链接，得到 404，历史列表为空。
2. 连续做 10 次会调用模型的操作后，第 11 次被拒绝并提示恢复时间；改字段仍可用。
3. 清除 Cookie 后，看不到旧记录，但同一 IP 的额度仍受 IP 上限约束。
4. 在设置里填入自己的 Key 并自测通过后，额度不再减少；填错 Key 时直接报错，额度也不减少。
5. 分别用 Gemini、Grok、DeepSeek 的 Key 完整走一遍：评估、补充抽取、详细分析、下载报告，全部不报错。
6. 打开浏览器开发者工具的网络面板，确认 Key 只出现在请求头，不出现在 URL 和请求体。
7. 抓取服务端日志，确认没有 Key 和用户输入的原文。
8. 直接用 `curl` 访问 `/api/save-config`、`/api/config`：返回 404。

## 部署清单（非代码，上线前逐项确认）

1. 反向代理提供 HTTPS，应用只监听 `127.0.0.1`，并用连接地址覆盖 `X-Forwarded-For`。
2. 托管 Key 必须是 Google 的付费档，并在 Google Cloud 里设置**预算提醒与支出上限**。免费档有共享的频率限制，且其内容可能被用于改进产品（以 Google 当前条款为准），不适合处理他人的收入和借贷信息。
3. `QUOTA_SALT`、`GEMINI_API_KEY` 只放系统环境变量，不进仓库、不进 `.env`。
4. 数据库文件所在目录权限收紧，并有备份与保留期之外的清理计划。
5. 用 `HOSTED=1` 在本机先完整跑一遍测试与手动验收，再上线。

## 明确不做

- 登录与账号体系、支付、更多厂商、自定义 Base URL。
- 多进程或多机部署（额度与频率限制都在单进程内存或本地 SQLite）。
- 在服务端保存用户自带的 Key。
- 浏览器直连厂商 API（各家 CORS 不同，还会暴露提示词）。
- 加密存储会话内容（本期只做归属隔离、保留期和删除）。
