# 实施方案 v2.4.1：v2.4 审阅后的修复补丁

背景：v2.4 的后端（归属隔离、额度、限流、Cookie、BYO 请求头、Grok/DeepSeek 适配器）大体到位，测试 50 项通过。审阅发现前端有一处会让"详细分析"在所有模式下报 415，第二、三期的前端没有实现，后端有 3 处缺陷。本方案只修这些，不扩范围。

原则同前：先写测试再改代码；不改评分规则，不改 `RULES_VERSION`；日志不含用户文字和任何 Key。交回：改动文件清单、`python -m unittest discover tests -v` 完整输出、`python tools/calibrate.py` 输出、第 5 节手动验收结果。

## 1. 阻断项（必须先修）

### 1.1 前端所有 POST 必须带 Content-Type；补齐 `api()` 封装
**现象**：
- `app.js` 的 `runAnalysis` 用 `fetch(url, { method: "POST" })`，没有 Content-Type 也没有请求体。服务端的 415 校验对所有模式生效，所以"查看详细分析"和"点击更新"现在必然返回 415。测试没发现，是因为测试请求带了 JSON 头。
- `initMode` 调用了 `api(...)`，但 `app.js` 里没有定义 `api`。异常被 `catch (_) {}` 吞掉，结果是：托管模式的额度徽标不显示、服务端设置入口不隐藏、保留天数不填充。

**做法**：
- 在 `app.js` 顶部先定义 `$`，再定义 `api(path, opts)` 和 `postJson(path, body, { llm })`：
  - `postJson` 一律带 `Content-Type: application/json` 与 JSON 请求体（无内容时发 `{}`）；
  - `llm: true` 时附带自带 Key 的请求头（见 2.2）；
  - 响应含 `quota` 时更新徽标；收到 429 且 `category` 为"额度用完"时显示提示并打开设置弹窗。
- `evaluate`、`append-text`、`analysis`、`fields`、`test-connection`、`save-config` 全部改用 `postJson`。
- `initMode` 不再吞异常：失败时在控制台输出错误，并显示一次温和提示。
- 测试：
  - 新增静态测试，读取 `app.js`，断言每个 `method: "POST"` 的 `fetch` 调用都带 `Content-Type`（或已改用 `postJson`），并断言 `function api` 已定义；
  - 服务端测试：无 Content-Type 的 `POST /analysis` 返回 415（锁定该行为）。

### 1.2 `_handle_analysis` 必须走 `llm.call_model`
**现象**：`_handle_analysis` 仍直接调用 `llm.call_gemini`。自带 Key 时 `base_url` 为 None，`validate_base_url` 判定不合法，三家自带 Key 的详细分析全部失败，并报"Base URL 不合法"。

**做法**：改为 `llm.call_model(prov, api_key, model, "analysis", "请根据以上信息进行详细会诊分析。", base_url=base_url, analysis_ctx=..., timeout_sec=...)`。`analysis_obj["model"]` 记录为"厂商 / 模型名"。
- 测试（mock `providers.urllib.request.urlopen` 或 `llm.call_model`）：自带 Key 的 `xai`、`deepseek`、`gemini` 各完成一次分析并成功保存；断言 `xai` 的自带 Key 从未被送往 Gemini 的地址。

### 1.3 额度退还要覆盖所有失败路径
**现象**：`/analysis` 失败（模型报错）时没有退还额度；其他两个端点也只在 `GeminiAPIError` 时退还，模型调用之后的任何异常（解析、校验、写库）都会白白扣掉用户的一次。

**做法**：三个调用模型的端点统一用"已扣费标志 + `try/finally`"：占用成功后置 `charged=True`，响应成功发出前置 `charged=False`，`finally` 中 `charged` 仍为真就退还。
- 测试：
  - `/analysis` 模型报错后，`used` 回到调用前的值；
  - `/evaluate` 中 `verify.verify_extracted` 抛异常后，`used` 回到调用前的值；
  - `/append-text` 同上。

## 2. 补齐第二、三期的前端（v2.4 方案 2.3、3.3 未实现的部分）

### 2.1 设置弹窗
- `index.html`：给现有服务端区块（Gemini Key、模型、Base URL、测试连接、保存）外面包一层 `id="server-cfg-wrap"`，仅非托管模式显示。
- 新增"使用我自己的 Key"区块（两种模式都显示）：
  - 厂商下拉：Gemini、Grok（xAI）、DeepSeek；
  - Key 输入框（密码框）；
  - 模型名输入框，默认值随厂商变化（Gemini `gemini-2.5-flash`、xAI 见 3.3、DeepSeek `deepseek-v4-flash`）；
  - 复选框"保存在本浏览器（公共电脑不要勾选）"，默认不勾选；
  - "测试连接并自测"按钮和状态区；
  - 选中厂商后显示一行数据流向提示："你的描述会发送给 <厂商>，按其数据政策处理"。
- 保存后不回显 Key，只显示掩码；提供"清除我的 Key"按钮。

### 2.2 请求头与存储
- `postJson(..., { llm: true })` 在 `byokState.key` 非空时附带 `X-LLM-Provider`、`X-LLM-Key`、`X-LLM-Model`。只有 `evaluate`、`append-text`、`analysis`、`test-connection` 四个请求带这些头。
- 勾选"保存在本浏览器"才写入 `localStorage`（键名 `cc_byok`）；取消勾选或点"清除"时删除该键并清空内存中的 Key。
- 隐私说明里的"默认 Google Gemini"改为随当前厂商变化。

### 2.3 额度徽标
- 使用自带 Key：显示"使用你自己的 Key，不占免费额度"。
- 否则托管模式显示"今日免费额度 x/10"，每次响应带 `quota` 都更新；额度为 0 时徽标变红，并指向设置弹窗。
- 分析报告里的"模型"一栏显示"厂商 / 模型名"。

### 2.4 测试
- 静态测试：`app.js` 中带 LLM 的请求都经过 `postJson(..., { llm: true })`；`X-LLM-Key` 只出现在 `postJson` 一处；没有任何地方把 Key 拼进 URL 或请求体。

## 3. 后端小项

### 3.1 清理线程只在托管模式运行
`_cleanup_loop` 现在无条件运行，本机自用时会静默删除 30 天前的会话。改为：`HOSTED=1`，或显式设置了 `RETENTION_DAYS` 时才启动。
- 测试：非托管且未设 `RETENTION_DAYS` 时不启动线程。

### 3.2 启动校验
- `HOSTED=1` 且 `ALLOWED_HOSTS` 为空：拒绝启动（否则所有请求都是 403）。
- `HOSTED=1` 且 `TRUST_PROXY` 不是 1：打印明显的 WARN。放在代理后面却不设该变量，所有用户会共用代理的 IP，IP 额度和限流会变成全站共享。

### 3.3 请求读取与默认模型
- `Content-Length` 为负数返回 400（现在 `rfile.read(-n)` 会读到连接关闭或超时）。
- 413 响应加 `Connection: close`，并设置 `close_connection = True`，避免未读完的请求体被当成下一个请求。
- `GET /api/sessions/{id}?version=abc` 返回 400，不要让异常冲出处理器。
- xAI 默认模型 `grok-3-mini-fast` 未经文档核实：用真实 Key 调 `GET /models` 对照 `docs.x.ai` 当前文档后设定，写在 `PROVIDER_PRESETS` 一处，前端默认值从 `/api/mode` 取，不在前端再写一份。
- DeepSeek 关闭思考的参数 `thinking: {"type": "disabled"}`：对照 DeepSeek 思考模式文档确认参数名与取值；并用真实 Key 确认 `max_tokens`、`response_format` 与该参数同时发送不会被拒。xAI 同样确认 `max_tokens` 与 strict `json_schema` 被接受（xAI 若要求 `max_completion_tokens`，则改用该参数）。
- `providers.test_openai_models` 改名为 `verify_openai_models`（避免被测试框架当成用例收集），并更新引用和测试里的 patch。

## 4. 测试补强
- `test_v24_phase1.py` 里"额度为 0 时改字段仍可用"的请求体用了 `{"updates": ...}`，被服务端忽略，用例实际什么也没验证。改为 `{"fields": [{"id": "cash_free", "value": 50000}]}`，并断言返回 200 且会话里该字段已写入。
- 增加：自带 Key 的 `append-text` 成功且不占额度。
- 增加：1.1 至 1.3 的用例。

## 5. 验收

### 自动
- 全部测试通过；校准四项硬性验收不变。

### 手动（必须用真实 Key，mock 测试证明不了厂商真的接受请求）
1. 非托管模式（本机）：原有流程不变，"查看详细分析"和"补充抽取"都不报错；30 天前的旧会话不会被删。
2. 托管模式（`HOSTED=1`，本机用 `ALLOWED_HOSTS=127.0.0.1,localhost` 先跑）：
   - 顶栏显示"今日免费额度 x/10"，每次调用后递减；
   - 两个浏览器互相看不到对方的会话；
   - 第 11 次调用被拒绝并提示恢复时间；
   - 让一次分析失败（例如临时改坏托管 Key），额度不变。
3. 分别用 Gemini、Grok、DeepSeek 的真实 Key 完整走一遍：自测通过、评估、补充抽取、详细分析、下载 HTML 和 Markdown，全部不报错。
4. 浏览器开发者工具的网络面板：Key 只出现在请求头，不在 URL 和请求体里；服务端日志没有 Key 和用户原文。
5. 未勾选"保存在本浏览器"时刷新页面，Key 需要重填；勾选后刷新仍在；点"清除"后 `localStorage` 里没有 `cc_byok`。
