## 4. 启动与配置

### 本机自用（默认，行为与以前一致）
复制 `.env.example` 为 `.env`，填 `GEMINI_API_KEY`，运行 `python server.py`，访问 `http://127.0.0.1:8100`。不要求 Cookie，不校验会话归属，不计额度。

### 托管模式（对外）
环境变量（systemd 的 `EnvironmentFile`，权限 600）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `HOSTED` | 0 | 设为 1 |
| `HOST` / `PORT` | 127.0.0.1 / 8100 | 应用只监听本机，由反向代理对外 |
| `ALLOWED_HOSTS` | 空 | 你的域名；为空时拒绝启动 |
| `TRUST_PROXY` | 0 | 设为 1，取 `X-Forwarded-For` 最后一个值；未设会打 WARN（所有用户会共用代理 IP） |
| `QUOTA_SALT` | 无 | 随机长字符串；缺失则拒绝启动 |
| `GEMINI_API_KEY` | 无 | **必须是付费档**，并在 Google Cloud 设预算提醒和支出上限 |
| `GEMINI_MODEL` | gemini-3.5-flash | |
| `FREE_DAILY_LIMIT` | 10 | 每个匿名用户每天的免费调用次数 |
| `FREE_DAILY_LIMIT_IP` | 30 | 每个 IP 每天 |
| `GLOBAL_DAILY_LIMIT` | 300 | 全站每天熔断 |
| `RETENTION_DAYS` | 30 | 会话保留天数；清理线程只在托管模式（或显式设置该变量时）运行 |

反向代理：Caddy 一个站点块 `reverse_proxy 127.0.0.1:8100` 即可（默认覆盖 `X-Forwarded-For`）；nginx 需 `proxy_set_header X-Forwarded-For $remote_addr;`。

上线后立即核对：`/api/mode` 的 `hosted` 为 true；`/api/config` 返回 404；首页 `Set-Cookie` 含 `Secure; HttpOnly`；日志中没有 `hosted_mode_without_trust_proxy`。

## 5. 核心机制：相对旧版第 4 节的变化

**评分与规则（`engine.py` / `score.py`）**
- 财务安全垫：未填"仍有收入"时，**该信号不评**（视为未知），只保留花费占比信号和黄色提示；不再固定评"中"。红线逻辑不变。
- `score.red_line` 布尔字段：红线时前端、历史列表、HTML 与 Markdown 报告都不显示置信度，改显示"由规则直接判定（红线）"。`_raw_confidence` 未改（清单的可提升量依赖它）。
- `score.excluded[*].rating_if_included`：用户手动排除的因子若本会评"低"，仪表盘和报告附"（若计入将评为低）"。
- EXECUTION 的关键字段不再包含 `past_projects`（该字段 `ui_show:false`，用户无法填写）。
- 低置信度时（置信度 <50% 或下界 <50）的行动词是"目前偏乐观，先补下面几项"，不是"值得认真推进验证"。
- **`RULES_VERSION` 仍为 "2.3"**，但安全垫与覆盖度规则已变，所以旧会话不会按新规则重算。新库无影响。

**字段与保存**
- 清空输入框会发送 `{"id":..., "clear":true}`，服务端置为 `missing`；空值提交被忽略；枚举校验读取注册表的 `choices`。
- 清空后的字段以 `source:"form"` 保存，之后"补充抽取"不会再覆盖它（有意为之，但页面上没有提示）。

**模型调用与 Key**
- 统一入口 `llm.call_model(provider, api_key, model, task, ...)`，内部分派到 `providers.call_model`。
- 三个 LLM 端点（`evaluate`、`append-text`、`analysis`）都用"已扣费标志 + try/finally"，任何失败都退还额度。
- 请求头：`X-LLM-Provider`、`X-LLM-Key`、`X-LLM-Model`（仅 LLM 端点和 test-connection）。带自带 Key 时：**不占额度、不回退托管 Key、忽略任何 Base URL、Key 不入库不入日志**。不提供自定义 Base URL，三家地址写死在预设里（xAI `https://api.x.ai/v1`，DeepSeek `https://api.deepseek.com`）。
- 托管模式下，托管 Key 的失败统一返回 HTTP 503 和固定文案"免费服务暂时不可用……"，细节只进服务端日志；自带 Key 和非托管模式带厂商返回的细节（前 200 字，Key 已打码）。
- 所有厂商请求带 `User-Agent: CCagent/1.0`。
- 思考参数回退：厂商返回 400 且请求带思考参数时，去掉后重试一次，**只有重试成功后才记住"不支持"**（Gemini 的 `thinkingConfig`、DeepSeek 的 `thinking`）。

**API 变化**
- 新增：`GET /api/mode`（含 `default_models`）、`GET /api/quota`、`POST /api/test-connection`（托管模式只接受自带 Key 请求头，每 IP 每小时 10 次，会跑一次固定文本的抽取自测）。
- 托管模式下 `/api/config`、`/api/save-config` 返回 404。
- 所有 POST 必须是 `Content-Type: application/json`（否则 415）；请求体上限 64 KB（413）；负的 `Content-Length` 为 400；输入文字上限 2000 字。
- 每个调用模型的响应都带 `quota: {limit, used, remaining, resets_at}`。

**安全与隐私要点**
- Cookie `cc_owner`：32 字节随机，`HttpOnly`、`SameSite=Lax`、托管模式 `Secure`；库里只存 SHA-256；IP 只存加盐哈希。
- 会话归属：读取、字段更新、补充抽取、分析、报告、删除、列表全部按 `owner_hash` 校验，不符一律 404。
- Host/Origin 白名单、`X-Content-Type-Options`、`X-Frame-Options: DENY`、`Referrer-Policy`。托管模式下 500 响应不回显异常文本。
- 已知边界：没有登录；清除 Cookie 就看不到旧记录；轮换 Cookie 可绕过个人额度，但受 IP 额度和全站熔断约束。

**前端（`app.js`）**
- `$`、`api()`、`postJson(path, body, {llm})` 在文件顶部；`postJson` 返回 `{ res, data }`，非 JSON 响应统一返回 `{error, category:"服务异常"}`。
- 设置弹窗：托管模式只显示"使用我自己的 Key"（厂商下拉、Key 密码框、模型名、"保存在本浏览器"、测试连接并自测、清除）；服务端配置区块 `#server-cfg-wrap` 仅非托管模式显示。
- 自带 Key 默认只存页面内存，勾选"保存在本浏览器"才写 `localStorage.cc_byok`。
- 顶栏额度徽标；额度用完（429）自动打开设置；服务暂不可用时错误提示旁有"打开设置"按钮。
- 隐私说明只更新 `#privacy-provider` 的厂商名，初始化时也会同步。

## 8. 已知取舍与决策记录（新增）

- 免费额度口径：每次调用模型算 1 次；改字段不调模型、不计数；一次完整体检约 2 次。
- 身份用匿名 Cookie + IP，不做登录；个人上限 10、IP 上限 30、全站上限 300。
- 自带 Key 只存浏览器，服务端不存；经过你的服务器，用户需要信任运营者。
- 不提供自定义 Base URL（避免 SSRF）；自带 Key 只支持 Gemini、Grok、DeepSeek。
- 会话存服务端，保留 30 天，用户可随时删除；隐私说明不对厂商的数据用途做任何担保。
- 免费档 Gemini Key 的内容可能被用于改进产品（以 Google 当前条款为准），因此托管 Key 必须是付费档。
- 先上线、后验证第三方厂商：这是用户的决定；界面标"测试中"作为缓解。
- 保留旧版决策：评级与评分由代码规则决定，LLM 不打分；取消"可加大投入"档位；"这组不适用于我"可被用来回避弱项，缓解措施是显著标注"评分未包含"；不引入第三方 Python 依赖。
