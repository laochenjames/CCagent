# 职业投入体检工具 · 交接说明

截至 2026-11-16。用于在新对话窗口继续工作：先读完本文，再读 `实施方案v2.3.md`，即可接续。

## 1. 这是什么

一个**本机运行的网页工具**（纯 Python 标准库 + SQLite + 原生 JS），用来评估"要不要投入做某件事"（副业、转岗、学习、创业等）。

产品形态是**杀毒软件式**，这是用户明确要求的（v1 做成报告式后被否）：
- 输入一句话，几秒内给出**模糊判断**（偏低 / 一般 / 偏高 / 还看不出来）和**置信度**。
- 下面**一次性列出所有可填项**（分 7 组），想填哪个填哪个，**填一项评分和置信度即时变化**，不用点提交，不调用模型。
- 详细分析按需生成（调用模型），可**下载报告**（HTML / Markdown）。
- 期望值只是**大致值**，不追求精确；不给"期望金额"，给的是评分区间 + 置信度。

起点是 `career/` 下的职业期望值 skill（`ai-career-investment-prompt-v1.0.md` 等）。当前工具把其中**能写成代码的规则**挪进了代码，LLM 只做信息抽取和文字。

## 2. 工作方式（已约定）

1. 用户先与 Claude 讨论。
2. 讨论结束后，**Claude 写方案文档**（`实施方案vX.md` 及配套提示词/资产文件）。
3. **AGENT（另一个编码代理）执行方案**。Claude 不直接改代码。
4. 用户把成果交回，**Claude 审阅**（通过文件系统 MCP 读代码）。

用户偏好：**客观中立、专业的建设性意见，有不切实际之处直接指出**；批判性思考后再输出；**尽量通用，专业性后续再补**。

## 4. 核心机制

### 4.1 哪里调用模型，哪里不调用
| 动作 | 是否调用 Gemini |
|---|---|
| 输入框打字 | 否 |
| "开始体检" | 是，1 次，只做**字段抽取**（快速模型） |
| "补充抽取"（再补充一段话） | 是，1 次，只做抽取 |
| 填写/修改/跳过清单项、"不适用"开关 | **否**，纯代码重算，毫秒级 |
| "查看详细分析/更新分析" | 是，1 次，主模型 |
| 设置里的"测试连接" | 是，1 次，很小 |

评分、置信度、评级、风险、最大短板、结论句子、`rule_note` **全部由代码产生**；LLM 的文字只出现在：抽取、各智囊的 `insight`/`next_step`、假设批判、两周验证、验证设计。LLM 失败时直接报错，**不做规则兜底**。

### 4.2 评分模型（`score.py`，常量集中在文件顶部，均为**经验值，未校准**）
- 6 个因子与权重：变现与需求 3、能力与渠道 2、时间与执行 2、划算程度 2、财务安全垫 2、止损设置 1。
- 评级→评分点：高 0.85、中 0.55、低 0.20；"无法判断"=未知，区间 [0.15, 0.95]，点估计 0.55。
- 已知因子区间半宽 = 证据半宽（事实 0、自报 0.05、估计 0.10、猜测 0.18，取已提供关键字段中最差的）+ 覆盖度附加（0.15×(1−覆盖度)），裁剪到 [0.15, 0.95]。
- 合成：**加权几何平均**（点、下界、上界分别连乘）。置信度 = 1 −（上界−下界）/80，展示上限 95%。
- 评估词：置信度 <0.25 → "还看不出来"；否则评分 <35 偏低、35–65 一般、≥65 偏高；置信度 <0.5 前缀"初步看法"。
- 红线：借贷或动用生活必需资金；已填"仍有收入"且净消耗下现金不足 3 个月；预计花费占现金 >25%。触发后上界 ≤25，评估词偏低，行动词"不建议投入"。止损线过早只提示，不触发红线。
- 不适用/排除：纯时间项目（不花钱且不影响主业）→ 财务安全垫不适用；`purpose=learn` → 排除变现、划算、能力三个因子；用户可对"变现与需求""划算程度"点"这组不适用于我"（通过隐藏字段 `excl_MONETIZATION`/`excl_OPPORTUNITY`，复用 `/fields` 接口）。被排除时权重重新归一，并在仪表盘/报告标注"评分未包含：…"。
- 会诊结论：对每个评级为低/中的已知因子模拟提升一档，取评分提升最大者为"最大短板"；点击可跳到对应分组。

### 4.3 各因子评级规则（`engine.py`）
- **变现**：陌生人付过钱→高；熟人付过钱/有人问价→中；无付费时有先例→中、无先例→低；都没提→无法判断。旧值 `paid` 按熟人处理。
- **能力与渠道**：技能（直接/相近/没有）与渠道（已有/没试过/没有）各评一档取较低。
- **执行**：三个信号取最低：近期实际÷计划小时（<0.5 低，<0.8 中，否则高）、过去12个月连续周数（<16 低，16–30 中，≥31 高）、过去类似项目持续率（仍在做但从未有收入记 0.5）。
- **划算程度**：单价×到手比例 ÷ 到手底线（<0.8 低，0.8–1.5 中，≥1.5 高）；只有客户价底线时用价格比，不混用口径。
- **安全垫**：两个信号取较低：生存月数（现金 ÷ 月支出减仍有收入；<3 低，3–6 中，≥6 高）、花费占比（>25% 低，10–25% 中，<10% 高）。**未填"仍有收入"时该信号固定评中**并给黄色提示（与方案"最高中"略有出入，见第 7 节）。
- **止损**：验证期 ≥ 首个付费月+2 且确认会停→高；时间满足但是否真停未知→中；否则低。
- AI 冲击、一致性两位**不评级**；一致性的真实检查在 `compute_flags`（黄/红标志）。

### 4.4 防编造与 lint（`verify.py`）
- 抽取项必须带 `quote`，且是用户原话的子串；数字必须能在 quote 里找到（含中文数字换算）；类别降级（未来量不能是"事实"）；表单锁定字段不被 LLM 覆盖。
- LLM 文字 lint：数字白名单（用户原话数字 ∪ 已知字段数值 ∪ 程序评级文案数字 ∪ {0,1,2,3,5,6,10,25,36}）、违禁措辞、阈值标注【用户确认】/【AI建议值】、AI 冲击标注"判断，不是数据"。违规的条目被替换为"（该条含…已隐藏）"。

### 4.5 前端要点（`app.js`）
- 整表渲染只用于首次体检、补充抽取、打开历史；**平时保存后只原地更新**（不重建清单，不重排分组，焦点不丢）。
- 保存队列：合并 + 同一时刻只一个请求在途；点选类控件即时保存，输入框 600ms 防抖，失焦/回车立即保存。
- 仪表盘吸顶，滚动约 120px 后收成窄栏（带滞后阈值）。
- 详细分析区注入的是服务端 `report.py` 已转义的 HTML 片段。

### 4.6 API
`POST /api/evaluate`；`POST /api/sessions/{id}/fields | append-text | analysis`；`GET /api/sessions`、`/api/sessions/{id}`、`/api/sessions/{id}/report?format=fragment|html|md`；`DELETE /api/sessions/{id}`；`GET /api/advisors | fields | config`；`POST /api/save-config | test-connection`。

## 5. 用量与成本（已讨论，未落地）

- 每次完整使用约 2 次模型调用。我的估算（**未实测**）：首次体检输入 3–4k token、输出几百；详细分析输入 4–5k、输出约 1.5k。
- 价格我没能从官网确认你所用模型的现价；公开资料里 Flash-Lite 档约 $0.30/$2.50、Flash 档约 $1.50/$7.50 每百万 token（输入/输出），近期还在调价，请以 Google 官网为准。按此粗算一次完整使用约 $0.007–$0.027。
- **风险点**：`llm.py` 没有设置思考档位。据公开资料，3.5 Flash 默认中等思考，思考 token 按输出价计费；3.5 Flash 用 `thinkingLevel` 而不是 `thinkingBudget`，两者同时发送会 400。建议抽取用最低档，详细分析用低档，并带"400 则去掉参数重试"的兜底；记录每次调用的 token 用量（只记数字）。
- **其他**：输入长度和调用次数没有上限；"更新分析"按钮请求期间不禁用；**免费档 Key 的数据可能被用于改进产品，不适合收集收入、现金等敏感信息，推广必须用付费档**。

## 7. 待办（最重要的在前）

### 7.1 v2.3 审阅发现（建议写成 v2.3.1 补丁方案）
1. **"不太确定"开关对单选/是否字段无效**：`app.js` 里用的是创建行时的 `f.value`，需要记录当前值或读取选中的芯片。
2. **竞态丢数据**：`_handle_append_text` 用 LLM 调用前的旧字段快照写新版本，会覆盖期间的清单编辑；`_handle_analysis` 不加锁，保存时无条件清除 stale。应在 LLM 返回后于会话锁内重新读取最新字段再合并，并比较字段指纹设置 stale。
3. **低置信度仍给积极结论**：例如校准用例 4（只填两个工时）按我手算区间约 43–95、置信度约 35%，仍显示"偏高——值得认真推进验证"。建议"值得认真推进验证"需置信度 ≥50% 且区间下界足够高，否则改成"目前偏乐观，先补下面几项"。
4. **`extract_prompt.md` 缺两条规则**（店/团队层面数字标含糊；不做性格推断），`target_scope` 标志依赖前者。
5. **测试与文档没跟上**：缺 `needs_cash` 未回答不触发红线、`rate_capability`、排除开关、`synthesis`、新卡片等用例；`test_report.py` 样例仍是旧结构；缺 `tests/calibration/RESULTS.md`、`tests/golden/RESULTS.md`；README 没写"不适用开关可被用来回避弱项"的取舍。
6. 次要：`/fields` 无服务端校验（类型、范围、枚举）；历史列表用 `innerHTML` 拼 `s.title`（应改 `textContent`）；lint 把"万一""千万""第四"等误判为数字；"更新分析"可并发点击；`_handle_analysis` 用库里旧结果而非重算；"仍有的收入"在财务安全垫组里排最后；Markdown 报告缺一致性标志与"待补"；未填收入分支有多余代码行，智囊库说明要同步。

### 7.2 之前提出、尚未写的成本补丁
思考档位 + token 用量日志 + 输入长度上限（如 2000 字）+ 单会话调用次数上限 + 分析按钮禁用 + 分析提示词精简（去掉"未提供"行）。可并入 v2.3.1。

### 7.3 后续规划（本期不做）

## 8. 已知取舍与决策记录

- 评级、评分、档位由代码规则决定，LLM 不打分：为了结果稳定，也让规则可展示；代价是智囊的"判断力"主要体现在文字上。
- 取消了"可加大投入"档位：自报数据不足以支撑。
- 主界面不再有双轴（回报预期/下行可承受性），五六个因子的评级保留在详细分析里。
- "这组不适用于我"是通用兜底，**可被用来回避弱项**，缓解措施是在仪表盘和报告里显著标注"评分未包含"。
- 所有权重、阈值、半宽都是经验值，**从未校准**。
- 不引入第三方依赖，因此不做 PDF/Word 直出；PDF 通过下载的 HTML 用浏览器"打印→另存为 PDF"。
- 日志不记录用户输入全文与 LLM 响应；会话支持硬删除。
