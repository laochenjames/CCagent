# 实施方案 v2.4.4：真实 Key 核实发现的问题修复

背景：用真实 Key 跑 `tools/verify_providers.py` 后发现：
- Gemini：预设默认模型 `gemini-2.5-flash` 返回 404（应用实际在用的是 `gemini-3.5-flash`）。
- DeepSeek：`GET /models` 实际返回 `deepseek-flash`、`deepseek-v4-pro`，预设默认 `deepseek-v4-flash` 不在列表里；聊天请求返回 402（该账号余额为 0，需要充值后才能验证抽取和分析）。
- xAI：`GET /models` 和聊天请求都是 403，被统一映射成"Key 无效或无权限"，看不出真实原因（可能是余额、权限、或请求头被拦截）。

原则：先写测试再改代码；不改评分规则；日志和错误信息不含用户文字和任何 Key。
**汇报要求**：逐条对照编号写"已完成 / 未完成 / 偏离"；声称"已修改"的位置贴出代码行。

## 1. 默认模型修正

- `PROVIDER_PRESETS["gemini"]["default_model"]` 改为 `gemini-3.5-flash`；`PROVIDER_PRESETS["deepseek"]["default_model"]` 改为 `deepseek-flash`。
- xAI 默认模型**暂不改**，等第 4 节的诊断结果出来再定（不要凭猜测填写）。
- `app.js` 里的 `BYOK_DEFAULTS` 只作为 `/api/mode` 失败时的兜底，值与上面一致（xAI 保持现状并加注释"待核实"）。
- `verify_openai_models` 在模型名不在列表里时，错误信息附上列表中的前 8 个模型名，例如"模型 X 不在可用列表中，可用模型：a, b, c…"，让用户能直接改对。
- 测试：`/api/mode` 返回的 `default_models` 中 gemini 为 `gemini-3.5-flash`、deepseek 为 `deepseek-flash`；`verify_openai_models` 的错误信息包含可用模型名。

## 2. 把厂商自己的错误信息带出来

现在 401/402/403/400/422 都被映射成固定文案，403 尤其含糊（余额不足、权限限制、请求被拦截都会返回 403）。

- 对 `call_openai_compat`、`verify_openai_models` 和 `call_gemini` 的 4xx 响应：解析响应体里的 `error.message`（或 `message`、或原文），截取前 200 个字符，把其中出现的 Key 字符串替换为 `***`，附在固定文案之后，格式如"Key 无效或无权限（厂商返回：……）"。
- 厂商返回内容只在 4xx 时附带，5xx 和网络错误保持现状。
- 测试：mock 一个 403，响应体含"your team has no credits"，断言错误信息包含这句话；响应体含 Key 字符串时断言被替换为 `***`；超过 200 字符被截断。

## 3. 请求头增加 User-Agent

Python 默认的 `Python-urllib` User-Agent 会被一些前置了防护的接口直接拒绝（返回 403）。给所有厂商请求（含 `verify_openai_models`、`call_openai_compat`、`call_gemini`）统一加 `User-Agent: CCagent/1.0`。
- 这个改动本身无害；是否解决 xAI 的 403 取决于诊断结果（见第 4 节）。
- 测试：mock 的 `urlopen` 收到的请求带该头。

## 4. xAI 的 403 诊断（需要真实 Key，由你本人执行）

`tools/verify_providers.py` 已更新：任一 xAI 或 DeepSeek 步骤失败时，会自动打印原始 HTTP 诊断（状态码、厂商错误体前 300 字，Key 已打码），并对比默认 User-Agent 和自定义 User-Agent 的结果。执行：

```
$env:XAI_API_KEY="..."; $env:DEEPSEEK_API_KEY="..."; $env:GEMINI_API_KEY="..."
python tools/verify_providers.py --list-models --diagnose --model gemini=gemini-3.5-flash --model deepseek=deepseek-flash
```

根据输出决定后续：
- 错误体提到余额或额度：给 xAI 账号充值后重跑；
- 默认 UA 为 403、自定义 UA 为 200：第 3 节即可解决；
- 错误体提到权限或 endpoint：在 xAI 控制台检查该 Key 的权限范围；
- 列表能取到：从中选支持结构化输出的非推理快速型号，作为 xAI 默认模型，修改 `PROVIDER_PRESETS` 与 `BYOK_DEFAULTS`；
- 若该型号不支持 `/v1/chat/completions`、只支持 `/v1/responses`：**不要在本方案里改适配器**，把结论带回来，另写方案。

DeepSeek 需要先充值（小额即可），之后用 `--model deepseek=deepseek-flash` 重跑，确认：抽取通过、抽到单价 800、详细分析通过，且日志备注里没有"rejected thinking"。
