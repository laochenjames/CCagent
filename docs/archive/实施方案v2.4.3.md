# 实施方案 v2.4.3：前端运行时错误修复与自动化防护

背景：v2.4.2 的前端把界面补齐了，但审阅 `app.js` 发现 3 处会让页面无法使用的运行时错误。52 项测试全绿，是因为这些测试只对 `app.js` 做字符串检查，从不执行它。这一类问题已经连续出现多轮（415、`api` 未定义、`$` 缺失、返回值误用），这次除了修复，还要加能真正执行前端代码的自动化检查。

原则：先写测试再改代码；不改评分规则；日志不含用户文字和任何 Key。
**汇报要求**：逐条对照本方案编号写"已完成 / 未完成 / 偏离"；声称"已移动""已修复"的位置，要贴出对应的代码行。

## 1. 阻断项（页面当前无法使用）

### 1.1 `$` 没有定义
**现象**：汇报称 `const $ = ...` 已移到 `app.js` 第 1 行，实际第 1 行是 `updatePrivacyNotice`，全文没有 `$` 的定义；`updatePrivacyNotice` 还出现了两份。脚本在第一个 `$("btn-edit-desc")` 处抛出 ReferenceError，所有按钮都没有绑定事件。

**做法**：在文件第 1 行写 `const $ = (id) => document.getElementById(id);`，删除重复的 `updatePrivacyNotice`。

### 1.2 `postJson` 返回值被误用
**现象**：`postJson` 返回 `{ res, data }`，且已经读完响应体。但 `btn-evaluate`、`btn-append`、`btn-test-cfg`、`btn-byok-test` 把返回值当成 Response 调用 `safeJson(res)`，会抛出 `res.text is not a function`。只有 `runAnalysis` 用对了。结果是"开始体检""补充抽取"和两个测试连接按钮全部失败。

**做法**：
- 统一写成 `const { res, data } = await postJson(...)`，删掉这些位置的 `safeJson` 调用。
- `postJson` 内部：响应不是 JSON 时，返回 `data = { error: "服务器返回非 JSON 响应（HTTP <状态码>）", category: "服务异常" }`，调用方统一用 `data.error` 展示，不再有两种错误路径。
- `btn-byok-test` 的成功提示读取 `data.message`（服务端返回了 `ok / parsed_ok / extracted_ok / message`），`ok` 为 false 时显示 `data.message`；`extracted_ok` 为 false 时提示"该模型可用，但抽取质量不足"。

### 1.3 隐私说明被覆盖，且内容错误
**现象**：`updatePrivacyNotice` 对 `<details id="privacy-notice">` 设置 `textContent`，会把 `<summary>` 和段落整个替换掉；写入的文案还有两处错误：保留期写成"7 天"（实际默认 30 天），并承诺"不会用于训练你的个人账号"（我们无法替厂商担保）。

**做法**：
- `index.html` 里把厂商名放进 `<span id="privacy-provider">Google Gemini</span>`，函数只更新这个 span 的文字。
- 保留期继续用已有的 `retention-days-text`（来自 `/api/mode`）。
- 删除"不会用于训练"之类的承诺；其余文案保持 `index.html` 现有内容。

- 清理 `app.js` 中其它重复定义（保留一份）。

## 3. 自动化防护（防止同类问题再次出现）

### 3.1 ESLint `no-undef`
- 新增 devDependency：`eslint`；配置浏览器全局环境；规则只开 `no-undef`、`no-redeclare`、`no-dupe-keys`。
- `package.json` 增加 `"lint": "eslint app.js"`。
- 这一条能直接抓住 1.1 这类错误。

### 3.2 jsdom 烟雾测试 `tests/js/smoke.test.js`
- 新增 devDependency：`jsdom`；使用 Node 内置测试运行器（`node --test`）。
- 加载 `index.html` 与 `app.js`，桩掉 `fetch`，用固定响应驱动页面。用例：
  1. 页面加载后没有未捕获异常；
  2. 点击"开始体检"：请求带 `Content-Type: application/json`；响应渲染后 `#result-section` 可见，`#score-label` 有文字（这一条能抓住 1.2）；
  3. 托管模式（`/api/mode` 返回 `hosted: true`）：额度徽标出现；评估响应带 `quota` 后徽标数字更新；
  4. 保存自带 Key 并勾选"保存在本浏览器"：`localStorage` 里有 `cc_byok`；之后评估请求带 `X-LLM-Key`；点"清除"后 `cc_byok` 不存在，之后的评估请求不带该头；
  5. 点击"查看详细分析"：POST 带 `Content-Type`，渲染分析片段；
  6. 切换厂商后，`#privacy-notice` 里的 `<summary>` 仍然存在，且页面文字不含"7 天"；
  7. `btn-byok-test`：服务端返回 `ok:true, extracted_ok:false` 时显示"抽取质量不足"。
- `package.json`：`"test": "npm run lint && node --test tests/js"`。Python 测试保持 `python -m unittest discover tests -v`。
- 两套测试都必须通过才算完成，汇报里贴出 `npm test` 的完整输出。

## 4. 真实 Key 核实（v2.4.2 第 3 节，仍未完成）

已提供 `tools/verify_providers.py`，**由我这边写好，需要有真实 Key 的人执行**：
```
$env:XAI_API_KEY="..."; $env:DEEPSEEK_API_KEY="..."; $env:GEMINI_API_KEY="..."
python tools/verify_providers.py --list-models
python tools/verify_providers.py --model xai=<上一步选定的模型名>
```
脚本只读环境变量，不打印 Key，输出一张核实表（模型列表、抽取、是否抽到单价 800、详细分析、token、耗时、思考参数回退日志）。
- 先用 `--list-models` 选定 xAI 的默认模型（选支持结构化输出的非推理快速型号），改 `PROVIDER_PRESETS`；
- 若 DeepSeek 一行日志备注里出现 `rejected thinking`，说明 `thinking` 参数被拒，对照 DeepSeek 思考模式文档修正；
- 若出现"输出被截断"，调整 `MAX_TOKENS_EXTRACT` / `MAX_TOKENS_ANALYSIS`；
- 完成后把核实表贴入汇报。
