# 实施方案 v2.4.2：v2.4.1 未完成部分的补齐

背景：v2.4.1 的后端修复已落地并核对无误（分析改走 `call_model`、三个端点的额度退还、负长度与 413、`version` 校验、启动校验、清理线程只在托管模式运行）。但 v2.4.1 第 2 节要求的前端（自带 Key 的设置界面）没有实现，`evaluate` 与 `append-text` 也没有接入统一封装，第 3 节要求的厂商核实没有结果。本方案只补这些。

原则：先写测试再改代码；不改评分规则；日志不含用户文字和任何 Key。
**汇报要求**：汇报必须逐条对照本方案编号，写"已完成 / 未完成 / 偏离"。未做的项不得省略，也不得在总述里写"全部完成"。

## 1. 前端（按 v2.4.1 第 2 节原样执行，补充如下）

### 1.1 `evaluate` 与 `append-text` 接入 `postJson`
- `btn-evaluate`、`btn-append` 的请求改为 `postJson(path, body, { llm: true })`，这样才会附带 `X-LLM-*` 请求头、更新额度徽标、处理 429"额度用完"。
- 现状的后果：即使用户配置了自带 Key，评估和补充抽取也不会带请求头，会占用托管额度；而且徽标只在详细分析之后才更新，评估后显示的额度是过期的。
- 响应里 `quota` 存在时更新徽标；使用自带 Key 时徽标显示"使用你自己的 Key，不占免费额度"。

### 1.2 设置弹窗
- `index.html` 必须真正存在这些元素，`app.js` 必须引用它们：
  - `id="server-cfg-wrap"`：包住现有的服务端 Key、模型、Base URL 区块，托管模式下隐藏；
  - `id="byok-provider"`（下拉：Gemini、Grok（xAI）、DeepSeek）；
  - `id="byok-key"`（密码框）；
  - `id="byok-model"`（默认值随厂商变化，取自 `/api/mode` 的 `default_models`）；
  - `id="byok-remember"`（复选框"保存在本浏览器（公共电脑不要勾选）"，默认不勾选）；
  - `id="btn-byok-test"`（测试连接并自测）与状态区；
  - `id="btn-byok-clear"`（清除我的 Key）；
  - 选中厂商后显示"你的描述会发送给 <厂商>，按其数据政策处理"。
- 托管模式下"设置"弹窗只显示自带 Key 区块，不再出现服务端配置（它们的接口在托管模式下是 404）。
- 保存后不回显 Key，只显示掩码。

### 1.3 存储
- 勾选"保存在本浏览器"才写入 `localStorage` 的 `cc_byok`；取消勾选或点"清除"时 `removeItem("cc_byok")` 并清空内存中的 Key。
- 自测按钮通过 `postJson("/api/test-connection", {}, { llm: true })` 发送，使用输入框里的值（尚未保存也可测试）。

### 1.4 其他
- 隐私说明里的"默认 Google Gemini"改为随当前厂商变化（使用自带 Key 时显示所选厂商）。
- 把 `const $ = ...` 移到文件顶部，不要依赖脚本执行时序。

### 1.5 测试
在现有静态测试基础上增强：
- 断言 `/api/evaluate`、`/append-text`、`/analysis`、`/api/test-connection` 只出现在 `postJson(..., { llm: true })` 调用中，不再有对它们的裸 `fetch`；
- 断言上面 1.2 列出的元素 id 全部存在于 `index.html`，且 `app.js` 都引用了；
- 断言 `app.js` 里有 `localStorage.setItem("cc_byok"` 和 `removeItem("cc_byok")`，并且 `X-LLM-Key` 仍然只出现在 `postJson` 一处。

## 2. 后端小项

托管模式下，`do_POST` 兜底异常不得把异常文本返回给客户端：返回固定的"服务器内部错误"，日志只记录异常类型。非托管模式保持现状（方便本机调试）。
- 测试：托管模式下，mock 一个会抛出带路径文字的异常，响应体里不含该文字。

## 3. 厂商核实（必须用真实 Key，结果必须写进汇报）

mock 测试证明不了厂商真的接受这些请求。逐项核实并记录：

1. **xAI 默认模型**：当前默认值 `grok-3-mini-fast` 没有经过文档核实。用真实 Key 调 `GET https://api.x.ai/v1/models`，对照 `docs.x.ai` 当前文档，选一个支持结构化输出的非推理快速型号，写进 `PROVIDER_PRESETS`（一处），前端默认值继续从 `/api/mode` 取。
2. **xAI 请求参数**：确认 `max_tokens` 被接受（若要求 `max_completion_tokens` 则改用），确认 strict `json_schema` 对本项目的抽取和分析两套 Schema 都被接受。
3. **DeepSeek 关闭思考**：确认 `thinking: {"type": "disabled"}` 被接受（日志里不应出现"rejected thinkingConfig"类的回退 WARN）；若被拒绝，对照 DeepSeek 思考模式文档记录正确的参数名与取值并修正。
4. **输出长度**：确认抽取 2048、分析 6000 的上限在三家都不会触发 `finish_reason == "length"`。

汇报里给出一张表：三家 × （自测、评估、补充抽取、详细分析、下载 HTML 与 Markdown），每格写通过 / 失败、HTTP 状态和 token 数，并附相关日志行。

### 手动（托管模式 `HOSTED=1` 在本机跑，再加非托管模式各一遍）
