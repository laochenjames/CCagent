## 2. A：现金红线与安全垫（P0）

### 2.1 问题
`rate_safety_net`、`red_line_reasons`、`compute_flags` 目前的条件是"生存月数 < 3 且 `needs_cash` 不为 False"。`needs_cash` 未回答也算"不为 False"，所以只要填了现金和月支出、算出不足 3 个月，即使这件事不花钱、工资照发，也会触发红线（评分封顶 25，行动词"不建议投入"）。生存月数也没有扣除继续有的收入。

### 2.2 新增字段（registry）
```json
{
  "id": "income_after_monthly",
  "label": "做这件事期间每月仍有的稳定收入",
  "type": "number", "unit": "元/月",
  "tier": "standard", "weight": 2, "priority": 105,
  "applicable_if": "cash_relevant",
  "ask_text": "做这件事期间，你每个月还会有多少稳定收入？（工资、租金等；没有就填 0）",
  "impact_note": "收入不中断，现金就不容易见底；没有这一项，只能按最保守的口径估算。",
  "ui_group": "财务安全垫", "ui_show": true,
  "ui_label": "做这件事期间，每月还有多少稳定收入（没有填 0）",
  "sensitive": true, "neutral_value": 0
}
```
放在"财务安全垫"组，顺序在 `monthly_expense` 之后。`score.py` 的 `FACTOR_KEY_FIELDS["SAFETY_NET"]` 加入 `income_after_monthly`。

### 2.3 新规则（`rate_safety_net`，两个信号取较低一档）
```
若 needs_cash 与 affects_main_job 都明确为 False → "不适用"
若 borrowing_or_essential_funds 为 True → 低（红线）

信号 S（生存压力），需 cash_free 与 monthly_expense(>0)：
    若 income_after_monthly 已提供：
        net_burn = monthly_expense - income_after_monthly
        net_burn <= 0 → 高（无生存压力）
        否则 months = cash_free / net_burn；<3 低；3 <= months < 6 中；>= 6 高
    否则（未提供）：
        months_gross = cash_free / monthly_expense
        评级 = min(中, 按 months_gross 的评级)，并在 rule_note 注明
        "未确认现有收入是否继续，按最保守口径估算，最高评中"
信号 O（花费压力），需 cash_outlay 与 cash_free(>0)，且 needs_cash 不为 False：
    ratio = cash_outlay / cash_free；>0.25 低；0.10 <= ratio <= 0.25 中；<0.10 高
综合：可得信号中取最低；无任何可得信号 → "无法判断"
```
`rule_note` 要写出代入的数字（沿用现有风格）。

### 2.4 红线与标志
`red_line_reasons` 改为只返回以下三类：
1. `borrowing_or_essential_funds=True`；
2. **`income_after_monthly` 已提供**，且 `net_burn > 0`，且 `cash_free / net_burn < 3`：文案如"现金 ÷ 每月净消耗 = X ÷ Y = Z 个月 < 3 个月"；
3. `cash_outlay / cash_free > 0.25`（要求 `cash_outlay`、`cash_free` 已提供）。

**不再依赖 `needs_cash` 是否为 False**，也不再在 `income_after_monthly` 未提供时触发生存月数红线。

`compute_flags` 同步：
- 红色标志与上面三类一致；
- 新增黄色标志：`income_after_monthly` 未提供、`cash_free` 与 `monthly_expense` 已提供且 `cash_free / monthly_expense < 3` → "如果这段时间没有稳定收入，现金大约只够 X 个月（尚未确认你的现有收入是否继续）。"

## 5. D：会诊结论（最强项 / 最大短板）

### 5.1 计算（`score.py`，纯函数）
在 `compute_score` 中，对每个**已知且评级为低或中**的纳入因子，模拟提升一档（低→中，中→高），用同样的权重重算评分点，得到提升量 `delta`：
- 最大短板 = `delta` 最大者；并列时取评级更低者，再并列取权重更大者；
- 最强项 = 已知因子中评分点最高者；若与最大短板是同一因子，则不显示最强项；
- 输出 `synthesis`：
```
{ "weakest": {"id","name","rating","delta"} | null,
  "strongest": {"id","name","rating"} | null,
  "group": "最大短板对应的清单分组名" | null,
  "sentence": "..." }
```
- `delta` 取整，且 > 0 时至少显示 1。
- 因子 → 清单分组映射常量 `FACTOR_GROUP`：MONETIZATION→变现与需求、CAPABILITY→能力与渠道、EXECUTION→时间与执行、OPPORTUNITY→划算程度、SAFETY_NET→财务安全垫、STOPLOSS→止损设置。

### 5.2 句子模板（代码生成）
- 触发红线：`"红线未解除前，改善其他项不会改变结论。"`
- 有最大短板：`"最大短板：{name}（{rating}），把它提升一档，评分约 +{delta}。"`，若有最强项再追加 `"最强项：{name}。"`
- 已知因子都评为高：`"已评估的项目目前没有明显短板。"`
- 没有任何已知因子：`sentence` 为空，前端不显示。

### 5.3 展示
- 仪表盘：headline 下一行显示 `synthesis.sentence`；点击"最大短板"文字滚动到对应分组并高亮 1 秒；紧凑（吸顶）模式隐藏。
- 报告：摘要章节在 headline 下显示同一句；评分依据表里把最大短板那行加粗并加"最大短板"徽章。
- `synthesis` 写入 result 对象，同时在传给详细分析提示词时放入 `{{SYNTHESIS}}`（格式：`最强项：…；最大短板：…（评级），分组：…`，没有则写"无"）。

## 6. E：智囊输出改造

### 6.1 `llm.py` 的 analysis schema
`advisors` 项改为 `{id, insight, next_step}`（均为 STRING，可为空字符串）。**去掉 `basis`、`missing`、`note`。** 提示词占位符增加 `{{SYNTHESIS}}`。其余（critique、two_week_checks、validation_design）不变。使用 `prompts/analysis_prompt.v2.3.md` 替换原提示词。

### 6.2 `server.py` 的 `_handle_analysis`
对智囊库的每一位成员生成输出对象：
```
{ id, name, dimension, rated, rating, rule_note, insight, next_step, missing }
```
- `rating`、`rule_note`：来自 `factors`；`rated=false` 的成员 `rating="不参与"`，`rule_note` 为空；被排除的因子（学习型或用户标记不适用）`rating="不适用"`。
- **`missing` 由代码计算**：该成员库里的 `reads_fields` 中，满足 `ui_show=true`、适用、状态不是 given 的字段，转为 `ui_label`，最多 3 个。不再由 LLM 提供。
- `insight`、`next_step` 经 lint（数字白名单、违禁措辞）；AI_IMPACT 的 `insight` 非空且不以"（判断，不是数据）"结尾时，由代码补上。
- LLM 对未知 id 或缺失成员：该成员 `insight`、`next_step` 视为空。
- 在 `analysis_obj` 加 `rules_version`（见第 10 节）。

### 6.3 `report.py`（页面片段与完整报告）
智囊卡片新结构（每位一张）：
1. 标题行：名称 + 一句话维度 + 评级徽章（"不参与"显示"不评级"，"不适用"显示"不适用"）。
2. "程序依据"：`rule_note`（浅灰小字，前缀"程序依据"）。
3. "缺少的信息"：`missing` 标签（有则显示）。
4. "AI 提醒"：`insight`（有则显示，前缀"AI"小标签）。
5. "下一步"：`next_step`（有则显示）。
6. 当 `insight`、`next_step` 均为空且评级为"无法判断"：显示"待补：{missing 标签}"，没有 missing 则显示"信息不足"。
7. AI_IMPACT、CONSISTENCY 两张归在"其他提示"小标题下；二者 `insight`、`next_step` 均为空时**整张卡片不显示**。
8. CONSISTENCY 卡片额外列出程序检出的风险标志（`flags` 中的黄色标志），不重复红色标志。
9. **兼容旧分析**：旧 `analysis_json` 里的智囊项含 `basis`、`note` 而没有 `insight`：渲染"依据（AI）：basis"、"提示：note"，不报错。

Markdown 导出同步。

## 7. F："这组不适用于我"（通用兜底）

### 7.1 机制
为"变现与需求""划算程度"两组各增加一个可标记"不适用"的开关（这两组最依赖"按次收费"的语义，用户的情形不匹配时无法填写）。**复用现有字段机制，不新增 API：**

registry 新增两个隐藏字段（`ui_show=false`）：
```json
{"id": "excl_MONETIZATION", "label": "变现与需求不适用", "type": "bool", "unit": "", "tier": "optional", "weight": 0, "priority": 900, "applicable_if": "always", "ui_group": "", "ui_show": false, "ui_label": "变现与需求不适用", "sensitive": false, "neutral_value": null},
{"id": "excl_OPPORTUNITY",  "label": "划算程度不适用",   "type": "bool", "unit": "", "tier": "optional", "weight": 0, "priority": 901, "applicable_if": "always", "ui_group": "", "ui_show": false, "ui_label": "划算程度不适用",   "sensitive": false, "neutral_value": null}
```
前端通过现有 `/api/sessions/{id}/fields` 提交 `{id:"excl_MONETIZATION", value:true|false, unsure:false}` 切换。

`score.py`：增加常量 `GROUP_EXCLUDE_KEY = {"变现与需求": "excl_MONETIZATION", "划算程度": "excl_OPPORTUNITY"}` 与 `FACTOR_EXCLUDE_KEY = {"MONETIZATION": "excl_MONETIZATION", "OPPORTUNITY": "excl_OPPORTUNITY"}`。
- 对应开关为 True 时，该因子从评分中移出（其余权重重新归一），其所在组内字段视为**不适用**（`is_field_applicable` 返回 False，不出现在清单、不参与覆盖度与 gain）。
- 学习型（`purpose=learn`）时，"变现与需求""划算程度""能力与渠道"三组自动不适用并隐藏，不可手动撤销。
- 输出 `score.excluded`：`[{"id","name","reason":"你标记为不适用"|"学习型不适用"}]`。

### 7.2 groups 输出
每个分组新增：`excludable`（仅上述两组为 True）、`excluded`（是否已被用户标记）、`auto_excluded`（学习型自动排除）。被排除的组：`state="不适用"`、`gain=0`、`fields=[]`。

### 7.3 展示
- 清单：可排除的组，标题行右侧放链接"这组不适用于我"；已排除时该组折叠成一行灰字"已标记不适用，评分不含此项 · 撤销"。点击后只**重渲染该组**（不整表重绘，沿用 v2.1 的原位更新原则）。
- 仪表盘：若 `score.excluded` 非空，在 `synthesis` 句子下面显示一行小字"评分未包含：{名称列表}"（紧凑模式隐藏）。
- 报告：摘要章节显示同一行；"评分依据"表里被排除的因子不出现，并在表下加注。

### 7.4 取舍说明（写入 README）
这是**通用兜底**，专业化的按类型定制字段留待后续。它的代价是：用户可以通过标记"不适用"回避自己的弱项。缓解措施是上面的三处显著标注；置信度计算不做特殊处理。

### 8.2 `rate_execution` 的信号 C 调整
对每个过往项目计"持续分"：
- `actual_months >= planned_months`（两者都有）→ 1；
- `still_running=true`：`had_income` 为 False → 0.5；其他（True 或未提供）→ 1；
- 其他 → 0。
持续率 = 持续分之和 ÷ 项目数；阈值不变（<0.5 低，0.5–0.67 中，≥0.67 高）。`rule_note` 如实写出。
