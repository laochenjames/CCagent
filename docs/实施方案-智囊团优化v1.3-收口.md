## 3. 任务

### H1　条数校验（缺口 1、2；D12/D13）

1. 新增 `parse_count(s)`：解析 `"3"`、`"3-4"`、`"4-5"`、`"2-3"`、`"3~4"`、`"3～4"`、`"3–4"`，返回 `(min, max)`；解析不到返回 `None`。
2. `validate_result` 按下表处理：

| 节类型 | 情况 | 处理 |
|---|---|---|
| 逐条目（有 `items`） | 条数 ≠ 配置条数 | 判错，进入同一次修复重试；修复后仍不符报错（沿用现行为） |
| 有 `count` | 条数 > max | 截断到 max，计数 |
| 有 `count` | 1 ≤ 条数 < min | 判错，进入同一次修复重试；修复后仍 < min 则放行，WARN 并计数 |
| 有 `count` | 条数 = 0 | 判错（沿用） |
| 无 `count` | 条数 = 0 | 判错 |
| 无 `count` | 条数 ≥ 1 | 放行，记录条数分布（D13：删除 8 上限） |

3. 修复重试的提示里要带上具体不符信息（例如"第二节要求 4~5 条，你返回了 1 条"）。修复重试仍受现有的 ≥35 秒剩余时间约束。
4. 配置自检：新增测试，遍历所有 `config.json`，每个含 `count` 的节必须 `parse_count` 非 `None`。
5. 修改既有测试：`test_g3` 第 4 项（8 条上限）按新规则改写；`_valid_mock_result` 对有 `count` 的节生成合规条数，`test_b2` 不得再让 1 条通过 "4-5"。
6. 新增测试：agent7 第二节分别返回 0/1/4/5/7 条，断言各自的处理结果；修复后仍为 1 条时放行并产生 WARN 与计数。

### H2　长度解析与上限覆盖（缺口 3、4）

1. `parse_max_len` 同时识别 `N字以内`、`N字内`、`N字以下`、`N~M字`（`~`、`～`、`-`、`–`，数字与"字"之间允许空格），区间取上限。
2. 新增全量 hint 覆盖测试：遍历全部 `config.json` 的 `title_hint`、`summary_hint`、`extract_summary_hint`、`synthesis_hint`、`pillars[].hint`、各节的 `item_name_hint`/`detail_hint` 及 `items[].name_hint`/`detail_hint`，凡含 `\d+\s*字` 的，`parse_max_len` 必须非 `None`，或登记在测试文件内的豁免清单里并写一句理由。输出一张"hint → 解析结果"的表，汇报里要贴。
3. 对 `consensus_text`、`tension_text` 套用 `synthesis_hint` 解析出的上限（取区间上限，1.5 倍硬上限，同 `_maybe_trunc`）。`extract` 返回的 `summary_note` 是否按 `extract_summary_hint` 截断，请核对现状：没有则加上；已有则在汇报中说明位置。
4. 测试补齐：`summary`、`pillars[].value`、`items[].name`、`items[].detail`、`consensus_text`、`tension_text` 各一个超长用例；`parse_max_len` 补 `"12字内"`、`"共识/分歧各 35~55 字"`、`"35字以内"`、`"14字以内"`。

### H3　夹具补全与机械反向校验（缺口 5；G1 补完）

1. **收窄 v1.2 的例外 ⑤**：只有"JSON 外层括号结构、占位示例文字"可以不搬。JSON 模板里的**长度、条数、标题、tag、name 提示**一律属于约束，必须进夹具。
2. 夹具条目结构扩展为 `{"text", "where": "generate"|"extract", "path"?, "kind": "wording"|"count"|"length"|"structure", "status": "required"|"changed"|"dropped", "old"?, "new"?, "reason"?}`：
   - `required`：新配置中必须存在，`path` 指向配置字段（如 `pillars[1].hint`、`sections[1].count`）。
   - `changed`：约束被有意改写；必须写 `old`、`new`、`reason`（一句具体理由，并引用对应决策编号 D 或 B 的原文要点）。
   - `dropped`：只允许 v1.2 的例外 ①–④，**一条约束一行、只归一个类别**，同样要写具体理由。
3. 新增 `tools/build_backup_constraint_index.py`（**需要 archive 存在，仅人工运行**）：用 `ast` 解析 agent4–10 备份，从 `_generate_ai`、`_extract_ai` 的全部字符串常量（含 f-string 的常量部分）中**机械提取**约束片段，不依赖 AGENT 的判断：
   - 所有含 `\d+\s*[~～-]?\s*\d*\s*字(以内|内)?` 的片段，
   - 所有含 `\d+\s*[~～-]?\s*\d*\s*(项|步|条|个)` 的片段，
   - "核心要求"块里以 `- ` 开头的每一行，
   - extract prompt 里的每一条指令句。
   输出 `tests/fixtures/backup_constraint_index.json` 并提交。
4. 新增单元测试（**不依赖 archive**）：索引里的每个片段必须能在夹具的某个 `text`/`old` 里作为子串找到。覆盖率不是 100% 则测试失败，并列出未覆盖的片段。
5. `tools/extract_backup_constraints.py` 保留，但把"备份里存在"检查与上面的索引生成合并，不再叫"可选"。
6. **汇报要求**：给出索引条数、已覆盖条数、未覆盖条数（必须为 0）；`changed`、`dropped` 条目各一张完整表（agent、原文、类别、理由）。

### H4　变异测试与按位置检查（缺口 6；G2 补完）

1. `_check_agent_constraints` 对 `required` 条目改为**按 `path` 取配置值检查**；另保留"渲染后提示含子串"作第二层。这样删掉三个 pillar 中的某一个 hint 就会被发现。
2. 新增表驱动的变异测试：对每个 Agent、每种变异在 `deepcopy` 的配置上执行，断言检查函数报出至少一处缺失（"变异被杀死"）：

   - 改动或删除任一 `pillars[i].hint`、

   - 删除 `synthesis_hint`、删除 `title_hint`、
